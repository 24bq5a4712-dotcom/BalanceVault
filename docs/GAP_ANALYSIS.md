# BalanceVault requirements gap analysis

**Review date:** 2026-11-11  
**Scope:** Read-only inspection of the active React client, Express API, Prisma
schema and migration, tests, configuration, and project documentation. This
review did not run builds, tests, migrations, or live integration checks.

## Assessment basis and limits

No separate Snovasys challenge brief, rubric, or acceptance-test document was
found in the workspace. The mandatory baseline below is therefore the set of
requirements explicitly requested in the project conversation: the specified
React/Vite, Express, PostgreSQL/Prisma, and Redis stack; auth and session
handling; holder/admin authorization; owner-scoped account management; admin
user onboarding and management; audit events; connected UI; and meaningful
tests. It is not a claim that this list exhausts the official challenge.

If the official brief requires transactions, budgets, income/expense reporting,
or other financial workflows, those items are missing from the active
application and must be added to the mandatory scope. The old
[static prototype](../client/src/App.jsx) is not active: the entry point imports
[BalanceVaultApp](../client/src/main.jsx).

**Status meanings:** Implemented means an active source path exists; Partially
implemented means a path exists but has a material limitation or validation
gap; Missing means no active implementation was found. Test coverage describes
the tests present in source, not a fresh test run.

## Highest-priority actions before submission

1. **Obtain and reconcile the official challenge brief.** The workspace does not
   contain it. Confirm whether transaction history, budgets, reports, or bank
   integrations are mandatory; those are not implemented in the active app.
2. **Resolve the Prisma dependency advisory.** The lockfile remains on Prisma
   6.19.3 / `deepmerge-ts` 7.1.5. Treat the three audit entries as one high
   severity dependency chain and complete a tested upgrade rather than
   suppressing the audit.
3. **Close session-revocation gaps.** Revoke existing sessions after password
   resets and sensitive account status/credential changes; add integration
   tests for immediate invalidation.
4. **Harden request validation/error behavior.** Reject malformed body shapes
   and return correct client-error statuses for malformed/oversized JSON, with
   route-level negative tests.
5. **Add frontend and accessibility verification.** Test the modal, keyboard
   focus, contrast, responsive breakpoints, loading/error states, and full
   user/admin journeys in an actual browser.
6. **Strengthen audit and data-integrity assurances.** Test transactional
   rollback, add before/after security-sensitive changes, and decide whether
   database constraints or external immutable retention are required.
